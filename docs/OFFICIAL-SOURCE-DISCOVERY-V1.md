# Official Source Discovery V1

Status: implemented candidate-generation boundary.

## Decision

Podium 7 adapts the mature official NHTSA vPIC and FuelEconomy.gov menu services for bounded U.S.-market source discovery. This is an `ADAPT` decision under `ADR-0001-MARKET-FIRST-INFRASTRUCTURE.md`; no generic crawler, browser, agent, discovery platform, or other new infrastructure is introduced.

Discovery is deliberately weaker than identity evidence. A discovery result means only that an official source exposed a source-native make/model/year or vehicle-menu candidate at an exact locator. It does **not** prove that the source label equals Podium's canonical model, trim, generation, configuration, or global identity.

Every returned `DiscoveryCandidate` therefore carries `evidence_role="discovery_candidate"` and `identity_proof=False`. Downstream entity resolution must use the normal Podium evidence rules before promoting any candidate into canonical identity.

## NHTSA vPIC adapter

The bounded method is `GetModelsForMakeYear`. Inputs are a non-empty make and model year 1996-2100. The adapter preserves:

- NHTSA `Make_ID`;
- NHTSA `Model_ID`;
- source `Make_Name` and `Model_Name`;
- the exact HTTPS request locator generated by Podium.

The parser requires an object with a list-valued `Results` and an integer `Count` exactly equal to the number of returned rows. Each row must contain a positive make/model ID and non-empty names, and the returned make name must match the requested make case-insensitively. A response that mixes multiple make IDs for one requested make fails explicitly. Repeated identical model IDs are deduplicated; conflicting records for one model ID fail.

This follows NHTSA's documented semantics: vPIC supplies manufacturer-submitted vehicle information and offers `GetModelsForMakeYear` for make/year enumeration, subject to automated traffic rate control and U.S.-market scope. It is not treated as a universal retail-specification source.

## FuelEconomy.gov adapters

Two existing menu surfaces are adapted:

1. `vehicle/menu/model?year=...&make=...` produces model-menu candidates. The menu `value` is preserved as the source model key and `text` as the source label.
2. `vehicle/menu/options?year=...&make=...&model=...` produces vehicle-option candidates. The menu `value` must be a positive numeric vehicle ID; `text` is preserved as the option label.

FuelEconomy menu responses may encode `menuItem` as either one object or a list. Any missing, malformed, empty, non-object, or conflicting duplicate representation fails explicitly. Identical duplicate keys/IDs are deduplicated.

FuelEconomy model and option labels remain source-native discovery labels. They are not silently decomposed into trim, drivetrain, engine, or configuration identity by this adapter.

## Nonclaims

Official Source Discovery V1 does not establish:

- canonical identity or automatic-match authority;
- global-market completeness;
- trim/configuration equivalence across NHTSA and FuelEconomy.gov;
- recurring robots/rate/politeness scheduling policy;
- arbitrary untrusted URL acquisition or strengthened SSRF/DNS-rebinding defense;
- production coverage or precision/recall beyond the bounded parser contracts.

## Validation contract

Permanent validation must prove deterministic locator construction, source-ID preservation, singleton/list menu handling, duplicate semantics, malformed-response rejection, and the invariant that discovery candidates cannot assert identity proof. Full repository CI remains the final integration evidence.
